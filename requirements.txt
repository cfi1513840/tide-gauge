# ------------------------------------------------------------
# Non-pip infrastructure & account requirements
# ------------------------------------------------------------
# These cannot be installed via this file. Listed here so they are
# not lost -- install.sh does not currently capture any of this.
# See the Technical Reference Manual, Requirements/Deployment
# section, for full setup detail.
#
# ACCOUNTS / EXTERNAL SERVICES:
#   - Notecard.io / Notehub.io account -- required for any station
#     using the Blues Notecard cellular path (SENSOR_SOURCE='notehub'
#     in tide.env). Notecard devices report to Notehub.io, which
#     routes data via webhook to tidenote.py's NotehubReceiver class,
#     integrated into tide.py's main loop via select.select() polling.
#   - Brevo (transactional email) account -- EMAIL_SERVICE='brevo' in
#     tide.env. Delivered via SMTP relay (smtplib, stdlib -- no pip
#     package required) using BREVO_SMTP_SERVER / BREVO_EMAIL_USERNAME
#     / BREVO_EMAIL_PASSWORD from the encrypted secrets store. A
#     non-Brevo SMTP_SERVER fallback path also exists if EMAIL_SERVICE
#     is set to anything else.
#   - Twilio account -- SMS delivery (see the twilio package below),
#     used for ADMIN_TEL_NBRS alert/status messages.
#   - Cloudflare account + cloudflared -- [Ken: confirm exact role here
#     for the manual -- tunnel to expose the Pi's web server without
#     port forwarding, DNS-only proxying, or something else?]
#   - InfluxDB -- installed and configured separately; runs as its own
#     service, not a pip package.
#
#     InfluxDB 3 MIGRATION (2026-08): each node now runs its own local
#     InfluxDB 3 Core instance (systemd service, localhost-bound) as the
#     primary write target, plus an InfluxDB Cloud Serverless account
#     (org TideGauge, bucket TideData) that a periodic sync process
#     pushes to. See INFLUXDB_LOCAL_* / INFLUXDB_CLOUD_* in
#     tide_constants_template.json, and fetch_tide() /
#     _sync_influxdb_cloud() in tidedatabase.py for read/write details.
#     The old flat INFLUXDB_TOKEN / INFLUXDB_READ_TOKEN /
#     INFLUXDB_READ_CLIENT fields were confirmed dead code (never
#     referenced for any actual read or write) and were removed as
#     part of this migration.
#
# REMOTE ACCESS:
#   - TigerVNC (server + viewer) -- remote desktop access, replacing a
#     prior paid RealVNC subscription. apt package, not pip.
#
# SYSTEM-LEVEL (apt, not pip):
#   - python3-tk -- required ONLY if running tidedisplay.py's local
#     Tkinter GUI display. NOT needed on headless Pi server nodes --
#     tide.py itself never imports tkinter.
#
# ------------------------------------------------------------
# Python 3.13+ compatibility note
# ------------------------------------------------------------
# The stdlib cgi/cgitb modules were removed in Python 3.13 (PEP 594).
# All CGI scripts (alertform.cgi, changealertpw.cgi, forgotpass.cgi,
# processalerts.cgi, reset-pw-1.cgi, valuser.cgi) still do
# `import cgi, cgitb` unmodified. legacy-cgi below is the officially
# recommended drop-in replacement (linked directly from Python's own
# docs for the removed module) and is confirmed working in production
# on tidebuddy (Python 3.13.5).
#
# This is a documented stopgap, not a permanent fix -- see the manual's
# Technical Debt section for the planned migration to
# urllib.parse.parse_qsl() (GET) and email.message (POST), per Python's
# own migration guidance.
legacy-cgi==2.6.4

# ------------------------------------------------------------
# Python package requirements
# ------------------------------------------------------------
argon2-cffi        # Password hashing (tidecrypto.py hash_password/verify_password) -- replaces Fernet encryption for the password field only (2026-07-13); email/phone remain Fernet-encrypted since those genuinely need to be recovered for sending mail/SMS, unlike passwords which only ever need verification
cryptography       # Fernet encryption for k1/k2/ku keys (tidecrypto.py, tidehelper.py, encrypt_constants.py, makekeys.py); k3/PASSWORD_KEY is retained only for verifying/migrating legacy-encrypted passwords, see tidecrypto.py
python-dotenv      # .env config file loading (tide.env) -- used across nearly every module
influxdb-client    # InfluxDB v2-compatible write API -- used for ALL writes (local and
                    # cloud), including the local write path in insert_tide()
                    # (tidedatabase.py) and the InfluxDB Cloud sync push in
                    # _sync_influxdb_cloud() (tidedatabase.py). InfluxDB 3's
                    # /api/v2/write compatibility endpoint accepts this unchanged --
                    # see InfluxDB 3 Migration note below.
influxdb3-python    # InfluxDB 3 native query client (import name: influxdb_client_3) --
                    # required for ALL queries against InfluxDB 3, local or cloud.
                    # InfluxDB 3 does NOT support the Flux-based /api/v2/query
                    # endpoint that influxdb-client uses for reads -- see
                    # fetch_tide() and _sync_influxdb_cloud() in tidedatabase.py.
                    # Pulls in pyarrow as a dependency (query results are Arrow
                    # tables). Install may take noticeably longer on Raspberry Pi
                    # (arm64) than the other packages in this file -- this is
                    # expected, not a hang.
pandas              # Required for converting InfluxDB 3 query results
                    # (fetch_tide(), sync_influxdb_cloud() in tidedatabase.py):
                    # InfluxDB 3 stores timestamps at nanosecond precision, and
                    # pyarrow's own to_pylist() cannot safely convert nanosecond
                    # timestamps to Python's microsecond-resolution datetime --
                    # it raises rather than silently lose precision. pandas'
                    # Timestamp type supports full nanosecond resolution, so
                    # to_pandas().to_dict('records') is used instead. (An earlier
                    # version of this code tried to avoid this dependency with
                    # to_pylist() directly -- don't re-introduce that without
                    # solving the nanosecond-precision problem some other way.)
pytz               # Timezone handling (tidealerts.py, tidedatabase.py, tide.py, tideplot.py)
requests           # HTTP calls to NDBC/OpenWeatherMap etc. (tideget.py, tidewxhtml.py)
urllib3            # Directly imported in tideget.py (import urllib3.util.connection), not relied on merely as a transitive dependency of requests
pyserial           # USB serial sensor reads (tideget.py, tidemonitor.py) -- import name is 'serial'
wget               # File download (tideget.py)
feedparser         # RSS/XML feed parsing (tideget.py)
twilio             # SMS delivery via Twilio account (tidehelper.py)

suntime            # Sunrise/sunset calculations (tidehelper.py)
suntimes           # Sunrise/sunset calculations (tideplot.py) -- NOT the same package as 'suntime' above
